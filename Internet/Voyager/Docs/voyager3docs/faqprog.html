Voyager V3 3.5. Historical FAQ by Benjamin C. Steeves (1997-1998), annotated for 3.5.

8.1 The Voyager program

Questions 2.1-2.20 of the 1998 FAQ.


What is the current version?

1998: Public Voyager was 2.95. There were separate 68000 and 68030+FPU executables. The 030/FPU build must not be used without an FPU; it was intended for 68040/68060 as well.

3.5: This build is Voyager 3.5 (classic 68k SAS/C). Last boxed product was 3.2 (16 April 2000); then limited 3.3 and a short 3.4 CVS series. There is one 68k executable, not a pair of 000/030+FPU binaries. See V.ReadMe and CHANGELOG.md.


Why does Voyager crash?

1998: Intermittent crashes were often other patches, old GUI hacks, or low memory. Update SetPatch. MCP helped some people; MCP mouse-blanking crashed the image decoder for others [Jason Eyre]. Low-memory handling could crash [Oliver Wagner]. Virtual memory (VMM on Aminet) could keep large JPEGs from killing the session; add tasks "V" and "V's Image Dec..." and press Return on the second name so VMM keeps the full task name [Sebastiano Vigna].

3.5: Same class of advice. Keep MUI and the TCP/IP stack current. Give Voyager Fast RAM. Image decode is linked into V, not a separate vimgdecode.library. VMM is still optional on 68k. If you report a crash, include Enforcer/MuForce output and what page you were on; send that to GitHub or voyager@amigazen.com, not a mailing list dump.


Why does Voyager eat CHIP RAM?

1998: Without a graphics card, bitmaps live in CHIP RAM. Disable the memory cache if CHIP is tight; quit and restart to free CHIP. On AGA, a Workbench screen uses less CHIP than extra custom screens. On a graphics card, images should go in card memory (usual default).

3.5: Still true on OCS/ECS/AGA. On RTG, cybergraphics.library is opened when first needed; screens are treated as CGX via IsCyberModeID. Prefer a CyberGraphX / Picasso96 / OS4 RTG screen for deep colour. Disk image cache is still a Settings item.


Why does Voyager use MUI?

1998: MUI (Stefan Stuntz) is a shared GUI toolkit. Wagner said Voyager would not exist without it: without MUI the executable would be larger, hungrier, and worse to write. Shared MUI libraries mean mailer, browser, and newsreader share one copy of the GUI code.

3.5: Still a MUI application. You need MUI 3.8 (or a later compatible MUI). Registering MUI is separate from Voyager. Tear-off panels are compiled off (USE_TEAROFF 0) because TearOff.mcc was not Enforcer hit clean. See MUI Tips in this manual.


Can I change the buttons?

1998: Toolbar images were built in. GIF copies in the home drawer were only for HTML docs. People asked for configurable buttons.

3.5: Settings / Toolbar lets you add, remove, and relabel buttons, pick icons from Buttons/, and set hotkeys. That is a V3 feature the 2.95 FAQ did not have.


Can I change the transfer animation?

1998: Yes. File TransferAnim in the program drawer is a horizontal strip of IFF brushes. WIDTH= in the .info tooltype is the width of one frame. General settings: uncheck Hide Transfer Anim Icon to show it. Datatypes are used for this anim, not for page GIF/JPEG/PNG (those are internal).

3.5: PROGDIR:TransferAnim is still loaded that way. Hide? in General settings still controls it. Page images remain internal decoders plus MIME helpers for other types; see mime.html.


Mail, news, and Find

1998: Fill in Mail/News (SMTP from your ISP). Need a current textinput.mcc (see below). Mail could be Internal SMTP, MicroDot II, or External. News was never internal; only MD2 or an external newsreader. The Find button was a plugin that queried four search engines in frames; Find-in-page was a Windows menu item.

3.5: Internal SMTP mailto: still exists; set address and mail host in Settings. MicroDot II paths (ENV:VAPOR/MD2_LASTUSEDDIR) are historical. Public NNTP from 1998 is largely gone; use an external client if you still have a server. The toolbar Find control is still the multi-engine search idea; use Windows / Find in page (or the RMB page menu) to search the current document. Old search-engine URLs in a plugin will often be dead; MIME still launches helpers for video/audio.


What is the Plugin drawer for?

1998: Search.VPlug shipped with Voyager. Voyager_SSLeay.vlib provided SSL. Other "plugins" were often MIME viewers (MPEG, WAV) from third-party sites. The plugin API lived on www.vapor.com.

3.5: Plugins/ holds voyager_ssl.vlib (AmiTLS, not SSLeay). MIME Prefs still start external viewers. Plugin SDK notes are in the source tree if present; vapor.com is offline. See faqssl.html for HTTPS.


Voyager invalidates my hard drive

1998: A crash while writing the disk cache can invalidate an OFS/FFS partition. Workarounds: put the cache on RAM:, RAD:, or a small partition that validates quickly; or disable the cache. AFS was mentioned as not invalidating (with other drawbacks).

3.5: Same FFS/OFS risk. Prefer a small cache partition or RAM: on flaky setups. SFS/PFS users still should not crash mid-write, but validation behaviour differs. Cache path is Settings / Cache.

Cache export: the 1998 cache browser Copy / Copy All dumped files to one directory and did not rebuild the site tree. Expect the same.


Second copy after a crash

1998: Empty file S:V-DEBUG allowed a second instance.

3.5: That file is not how 3.x starts. Voyager uses a public port named VOYAGER. A second start tries to send ARexx LoadURL NEW to the first copy and then exits. If the first copy is wedged but the port remains, you may need to break that task (or reboot) before V will start again. Do not leave a zombie V occupying the port.

Floppy-only: the 1998 FAQ said a minimal MUI plus V on one disk was possible with cache in RAM and almost no downloads. 3.5 with AmiTLS and certificates is not a floppy product. Use a hard disk or CF/SD.


Datatypes, printing, black boxes

1998: JPEG, PNG, and GIF are internal. Datatypes are for TransferAnim. Printing was screen-resolution, not printer dpi; no deeper than 8-bit (printer.device); long pages often printed one sheet on laser/inkjet because the page was one big bitmap and drivers missed formfeeds. Epson emulation / Canon Europe drivers in Epson 48-pin mode helped some BJ users [The Duke of Prunes]. Black boxes: old CyberGraphX and/or picture.datatype.

3.5: Internal image codecs unchanged in spirit. Printing is restored (it was missing in the 3.3 line): Print dialog, menu, toolbar, ARexx Print ASK. Text dump to PRT:; graphics via printer.device bands; TurboPrint if Turboprint: is assigned. Quality is still Amiga printer.device class, not a modern print engine. Keep CyberGraphX / Picasso96 current if RTG images are black or corrupt; picture.datatype still matters for the anim.


Slow start and quit

1998: CompuGraphic fonts in the Fonts settings (CGTimes, CGTriumvirate, LetterGothic) are scaled at startup; make bitmaps with Fountain (OS2) or Intellifont (OS3), or use bitmap fonts. Quit updates URL-History; a long "followed links expire" plus a disk cache makes that file huge. A nearly full small cache partition is also slow; format it now and then.

3.5: Same. Prefer bitmap or pre-generated CG sizes. Trim history expiry if quit is slow. Disk cache settings are under Cache.


textview.mcc and textinput.mcc

1998: Pre-2.88 used Textview.mcc (E. F. Pritchard). Wagner wrote Textinput.mcc to replace it. Install the class in LIBS:MUI/. Do not delete MUI classes; move them aside until you know nothing else needs them.

3.5: Still Textinput.mcc (and other classes in the Voyager Libs drawer). Keep those with the program or in MUI:Libs as you installed them.


I wrote to Olli and he never wrote back

1998: Wagner printed bug mail and BugTrack, marked known/fixed, and often did not reply. Include config, patches, Voyager state, and Enforcer hits. Do not post huge Enforcer logs to the mailing list.

3.5: Oliver Wagner died in 2016; Voyager V3 is dedicated to his memory. Do not mail historical VaporWare addresses. Open a GitHub issue.
